# OCTS AI — Phase 5: Refinement Engine, Bounding & Telemetry

## 1. Component Overview
The `RefinementEngine` serves as the central coordination facade for autonomous self-correction. It combines:
- `FeedbackBuilder`: Rubric gap analysis and prompt compilation.
- `RecoveryManager`: Bounded attempt management with hard safety ceilings.
- `RefinementController`: State assessment and routing decision logic.
- `ImprovementAnalyzer`: Multi-dimensional evaluation comparison and best-artifact selection.
- `ReviewSynthesizer`: Consolidated feedback generation.

---

## 2. Configuration & Attempt Bounding Invariants

### Single Source of Truth
The configuration is strictly managed via `backend/config.py` using Pydantic validation:
- `refinement_max_attempts: int = Field(default=2, ge=0, le=5)`
- `refinement_threshold: float = Field(default=70.0, ge=0.0, le=100.0)`
- `refinement_enabled: bool = Field(default=True)`

### Hard Safety Ceiling
`RecoveryManager` validates and enforces a hard ceiling of 5 attempts:
```python
class RecoveryManager:
    MAX_SAFETY_CAP = 5

    def __init__(self, max_attempts: int = 2):
        if max_attempts < 0:
            raise ValueError("max_attempts cannot be negative.")
        if max_attempts > self.MAX_SAFETY_CAP:
            raise ValueError(f"max_attempts cannot exceed safety cap of {self.MAX_SAFETY_CAP}.")
        self.max_attempts = max_attempts
```

### Dynamic LangGraph Recursion Limit
To prevent recursion limit exhaustion in multi-turn refinement loops, `OrchestrationExecutor` derives the recursion limit dynamically:
$$\text{safe\_recursion\_limit} = \max(\text{max\_recursion\_limit},\ 15 + 8 \times \text{max\_attempts})$$
For default $\text{max\_attempts} = 2$: $\text{safe\_recursion\_limit} = \max(25, 31) = 31$.

### Reviewer Calls Independence
Reviewer calls are auxiliary collaboration actions and do NOT increment `recovery_attempts`. Only generator refinement attempts increment `recovery_attempts`.

## 3. Weak Criteria Identification & Craft Remediation

The `FeedbackBuilder` scans the `criteria_breakdown` generated by Phase 4 evaluation:
- Identifies every criterion where `score < threshold` (default `70.0`).
- Computes the gap: $\text{gap} = 100.0 - \text{current\_score}$.
- Sorts identified criteria in descending order of gap so the most severe deficiency is prioritized.
- Emits structured `CriterionFeedback` objects containing:
  - `criterion_id`
  - `criterion_name`
  - `current_score`
  - `gap`
  - `deficiency_summary`
  - `actionable_recommendation`

Actionable recommendations are mapped directly to domain craft heuristics (narrative causality, metric stress alignments, harmonic voice leading, cognitive load reduction, WCAG AAA tokens).

---

## 4. Targeted Refinement Directives
The refinement prompt supplied to the specialist persona enforces 4 mandates:
1. **Preservation Mandate:** Explicitly highlights verified strengths identified by peer review to prevent catastrophic forgetting.
2. **Priority Remediation Mandate:** Directs attention to specific criteria failures and provides concrete fixes.
3. **Completeness Mandate:** Strictly prohibits partial drafts, diffs, apologies, or conversational meta-commentary ("Output a COMPLETE, fully realized new version").
4. **Persona Constraint Mandate:** Re-asserts the persona's foundational craft rules and negative constraints.

## 5. Performance & Telemetry Tracking

Every execution tracks granular latency and call counters:
- `initial_generation_latency_ms`: Duration of initial model generation.
- `peer_review_latency_ms`: Duration of specialist peer review execution.
- `refinement_generation_latency_ms`: Duration of author model refinement generation.
- `evaluation_latency_ms`: Cumulative duration of Phase 4 evaluation engine invocations.
- `total_refinement_latency_ms`: Sum of peer review and refinement generation latencies.
- `model_call_count`: Total generation model invocations (initial + refinements + LLM reviewer if used).
- `reviewer_call_count`: Total peer reviewer invocations.
